    Tour renderer (--tour)

    A deterministic, scripted render of the real UI for the walkthrough video, chapter clips and the interactive tour page. The app runs on a fixed 60 fps simulated clock at 1920x1080, a synthetic cursor drives the UI, and every frame of FBO 0 is read back and piped to ffmpeg (libx264). Same script + same library + same machine/GPU = bit-identical frames.

    ./gradlew run --args="--tour=scripts/tour_phase3_test.json --tour-out=/tmp/t/raw.mp4 --no-audio [--tour-hidden] [--tour-dump=<dir>:70,81]"
scripts/render_tour.sh --draft tours/overview.json tours/draft/overview --tour-hidden   # while writing: a few minutes for the 5 min overview
scripts/render_tour.sh [--webm] tours/overview.json tours/out/overview --tour-hidden     # final: hero.mp4 (+ .webm), poster, .vtt, captions.json, chapters.json, clips/ (whole chapters, 1080p30), loops/ (landing cards); cuts made by scripts/tour_cuts.py
scripts/render_tour.sh [--draft] --all tours/out --tour-hidden                           # every tours/*.json into tours/out/<name>/
scripts/tour_determinism_check.sh <script.json> --tour-hidden [--tour-draft]   # renders twice, compares per-frame SHA-256

    Render settings come from the command line, not the script (the website's renders use --tour-fps=30 --tour-encoder=nvenc --tour-no-hashes: the site plays 30 fps, NVENC output is reproducible on the same machine, and hashes are only for determinism checks; about 10 minutes for all seven videos instead of 1.5 hours): --tour-fps=<n> (default 60), --tour-scale=<f> (the UI is always laid out at 1920x1080; the frame is shrunk on the GPU before readback, so targets never move), --tour-encoder=x264|nvenc (default x264), --tour-hashes (per-frame SHA-256, about 5 ms a frame at 1080p). --tour-draft = 30 fps, scale 0.5, NVENC, no hashes. On the dev laptop (RTX A2000) a final frame costs about 20 ms (app and UI about 6, hash 5, x264 4, readback 3) and a draft frame about 11 ms, at half the frame count. Drafts are deterministic too (raw and NVENC-encoded frames, checked on this machine). TOUR_GL names the GPU the app rendered on and TOUR_TIMING gives the per-frame breakdown. VP9 has no hardware encoder here, so --webm is opt-in and slow.

    Tour mode isolates itself: preferences are not read or written, MIDI/OSC/Link/watchers/live audio are off (a script with audio still shows the AUD column), imgui.ini is not used, real GLFW input is ignored, randomness comes from DeterministicRandom(seed). Library contents are part of the input: pin a small curated library for the final render.

    Script format (tour/TourScript.kt)

    Top level: durationSec (optional: defaults to the last step's end plus tailSec), seed, audio (file fed to the analyzer by frame clock and muxed), bpm (manual beat clock), burnCaptions (draw captions into the video; the .vtt is always written; the tour page shows captions as text under the player, so only overview.json, whose full video is published, should burn them in, and its chapter clips will carry them until the render pipeline can make clips from a caption-free pass), captionStyle (cursor, the default, or bottom), tooltips (ImGui hover tooltips, off by default so they never collide with the caption box), chapters ({t, id, title, endSec?, clipSec?}, or use chapter steps), steps.

    Timing: a step starts at absolute t seconds, or dt seconds after the previous step (dt alone is the easiest to edit: inserting a step shifts everything after it). Captions: caption on any step becomes a cue lasting until the next captioned step ("" clears). {ch:<id>} in a caption becomes "Ch. N at m:ss". With captionStyle: cursor the caption is an opaque box beside the last move target, below it by default; captionPos (above, left, right) on the captioned step keeps it clear of what the step shows. The box stays put during drags and clicks.

    Checks printed as TOUR_WARN: a caption shown for less than its reading time (14 characters per second, at least 2.5 s), a chapter's last caption shown less than 5 s (or its reading time) before the chapter or video ends (the tour page autoplays the next chapter; lengthen the gap before the next chapter step, or tailSec for the last, rather than freezing: the app keeps running live meanwhile), a target that was not drawn in the previous frame (wrong page or view, or a move on the same frame as a page switch: wait about 0.4 s), unknown ids.

    Action Fields
    move target (widget key) or x,y; durationSec; ox,oy offset from the target's centre. Also draws a highlight ring on the target. An open combo's items sit about 17 px apart starting 16 px below the combo's centre (oy 16, 33, 50, ...)
    click / rclick / drag click (or right-click) at the cursor; drag presses, travels dx,dy (or onto target / absolute x,y, with ox,oy) over durationSec, releases (aim with a move first). Before a second drag on the same control, move back onto it: a drag ends where the cursor stopped
    hold caption only
    type / key / scroll type: target = text; selects the focused field's text (Ctrl+A), types it, presses Enter (click the field first). key: target = [ctrl+][shift+] enter, escape, tab, space, backspace or a letter, e.g. q, shift+q, ctrl+z (app shortcuts fire; Escape in Edit also collapses the rack). scroll: value wheel notches at the cursor
    chapter target = id, title, clipSec
    tooltips value 0 or 1
    set_page target = ab, bgpv, mixer
    library_mode, theme, preferences, preferences_close, output_view, randomization FULL/HALF; light/dark; category name; value 1 = Output View on (the F key), 0 = off; value 1/0 = randomization on/off (shows the Clock row's randomize buttons)
    open_params, open_params_pair, focus_pair, close_focus module id / pair tag
    load_source, load_preset deck A/B/BG/PV, target = source id / .lsd path
    set_param, bind_modulator deck, param, value; modulator target = CV source id, unit BEAT/TIME
    fx_filter, fx_enable, fx_link, fx_param, meta_knob deck (A/B/BG/PV/MASTER), slot 0-2, target/value/param
    fx_chain_enable deck, value 0 or 1: the chain's BYPASS switch (0 = bypassed)
    fx_swap deck, slot, slot2 (a real drag of one slot cell onto another does the same through the UI)
    fx_chain, fx_clear, fx_new, fx_dry_wet, super_knob deck, .lsdfxchain path / value (fx_new = the chain menu's New Chain: empty slots, named Untitled). super_knob and meta_knob set the FX row's macro knob, as a hand would; soft takeover still applies
    transition, transition_preset, crossfade stock id, .lsdtrans path, value -1..1
    trans_param param (ISF NAME), value: turns the Transitions row knob bound to it (knobs 2-4 drive the first three float parameters every tick), else sets it
    deck_level deck A/B/BG/PV, value 0..1: as a hand on the deck's level fader (Mixer.setLevelByUser)
    pipe target show (opaque backdrop, empty diagram), hide, reveal (the diagram shrinks into the mini-map over durationSec while the UI fades in)
    pipe_add target = comma list of groups decks, fx, trans, bg, master, pv; fade and slide in over durationSec
    pipe_focus target = node, chain (A.fx .. PV.fx, master) or all; the camera eases there over durationSec and dims the rest
    pipe_params target = node, params = list of ISF NAMEs: boxes with the parameter's label and live value bar, wired into the node (empty list clears)
    pipe_controls target = a shown parameter: the fan of control icons (knob, audio, LFO, sequencer, MIDI/OSC) wired into it; value 0 hides, 2 flashes the wires
    pipe_tag target = node, title = chip text beside its title; value 0 removes
    pipe_minimap target = comma list of nodes or groups to light (all, a group, a node, A.fx for a chain); durationSec (default 2.5); x,y moves the corner (default bottom-left)

    set_param, fx_param, trans_param, crossfade and meta_knob take durationSec to ease from the current value. fx_param warns when the slot's Metaknob owns the parameter (its value would be overwritten); turn meta_knob instead. A chapter step's minimap shows the pipeline mini-map at the chapter start with those nodes lit; every chapter of every video has one, so a clip watched on its own still shows where it sits in the pipeline.

    Unknown targets print TOUR_WARN and are skipped; treat any warning as a script bug.

    Pipeline diagram (tour/PipelineDiagram.kt)

    A live schematic drawn on the foreground draw list, under the cursor and caption, in a 1920x1080 design space. Nodes: decks A, B, BG, PV; FX slots A.fx1 .. PV.fx3 and master.fx1 .. master.fx3; trans, behind (the A/B mix over BG) and out. Each box shows the real texture at that point: deck source (cleanFBO), each FX slot's output (rendering/FxSlotTaps: a 384x216 copy per rendered slot, made only while the diagram is up; an empty or bypassed slot shows its input), the transition (blendFBO), the composite (masterCompositeFBO) and the output (masterFBO), over a checkerboard so transparency shows. A camera (screen = p * s + o) eases between the overview, a focused node and the mini-map. move targets: pipe:<node>, pipe:A.fx / pipe:master (a chain), pipe:param:<NAME>, pipe:control:<0-4>; they resolve where the camera is heading, so move after a focus has settled. The intro using it is the first chapter of tours/overview.json (pipeline); plan and storyboard in .planning/pipeline-intro-plan.md.

    Widget keys (tour/WidgetRegistry.kt)

    Call sites do WidgetRegistry.note { key } right after the ImGui item (free outside tour mode). Keys: perf_tab_<page>, perf_<page>_r<row>_c<col> (knobs), perf_gen_badge_<tag>, perf_src_more_/save_/eject_/rand_<tag>, rack_chevron_<id>, crossfader_track, fxcell_<bank>_<slot>, fxbypass_/fxlink_<bank>_<slot>, fxchain_name_<bank>, fxpill_<bank>_<slot>, fxchainlink_<bank>, fxchain_bypass_<A|B|BG|PV|MST> (chain BYPASS), fxchain_save_<bank>, fxchain_more_<bank> (chain Save and menu), focus mode fxwet_<bank> (Wet slider), fxpage_prev_/next_<bank>, fxfocus_name_<bank>, Transitions row perf_trans_picker, perf_snap_A/B, perf_autofade, perf_fade_time, perf_trans_rand (only with randomization on), browser_tab_<mode>, browser_search, browser_row_<src|fx|trans>_<stock id or file name without extension> (list rows; only rows scrolled into view are clickable), deck_fader_<A|B|BG|PV> (preview faders), prefs_cat_<category>, ui_theme, edit_side_<tab>, macro_name_<bank>_<label>. Edit grid: cv_<param path>_<label|val|midi|lfo|seq|audio> (param path as in <out>.keys, e.g. cv_Deck A/View/Zoom_lfo), grid_cols_kebab, grid_col_<midi|lfo|seq|audio>. Modulator panel: mod_power_<n>, mod_op_<n>, wave_lfo1_<sine|tri|square|random|left|center|right>, lfo_unit, aud_band, aud_profile, seq_unit, seq_bars_<row> (one key per row of up to 16 step bars; aim inside it with ox/oy or drag), range_<label>_<min|max> and slider_<label>_<value|min|max|track> (by the slider's label), and btn_<visible label> for every ButtonChrome.button (last drawn wins when labels repeat), plus btnid_<id after ##> when the label has an id (stays put when the text changes, e.g. btnid_perf_clock_tap, btnid_perf_q_next_B, btnid_cancelSavePreset). <out>.keys lists every key seen during a render, handy when authoring. Custom-drawn items without an ImGui item (deck title badges, knob strip labels) need x,y or a new explicit rect. Do not key on ##title_badge_*_x_y (coordinates in the id).

    Outputs next to --tour-out

    .hashes (per frame), .vtt, .captions.json (index/start/end/chapter/text for the web page and transcript), .chapters.json, .ffmeta (ffmpeg chapters). render_tour.sh derives the rest.

    Known leftovers: wall-clock use in FileSystemManager, DeckOps autosave names, PlaylistManager, PerformanceStats, TouchConsoleController (no pixel effect so far); other GPUs/compositors unverified.

    The walkthrough videos

    One script per video in tours/: overview.json (seven chapters, about 8 minutes, opening with the pipeline diagram), modulation.json (grid, LFO, audio, step sequencer, muting; about 4 minutes), and first drafts of fx_chains.json (about 4.8 minutes), mixing.json (3.8), library.json (2.8), hardware.json (2), output.json (2), each to be embedded on its user-guide page. A UI change re-renders only the videos it touches. In a deck's bound Browse (click the source name) a single click on a row loads it, so scripts show loads with move + click on browser_row_* keys instead of load_source. Things tour mode cannot show: MIDI and OSC are off, so their Preferences panels show the disabled state and nothing arrives (the learn ring and panels are what the Hardware video shows); a menu or modal opened by a click is real (avoid items that open windows or write files, close Save dialogs with btnid_cancelSavePreset); Output View is output_view, not the F key (GLFW key callbacks are ignored). Their soundtrack tours/beat.wav is a generated placeholder (scripts/make_tour_beat.sh, not committed) until the licensed track arrives; the script only names the file, so swapping it changes nothing else.

    The website tour page

    scripts/build_website.py generates /tour/ from the rendered videos (--tours DIR; default tours/out if it holds a render, else tours/draft). Video order, titles, summaries and the docs page each video links to live in website/data/tour.json. For every chapter it copies clips/<id>.mp4 (the whole chapter, silent) to tour/media/<video>/ and loops/<id>.mp4 (its first clipSec, at most 20 s) to tour/media/<video>/loops/ for the chapters landing.json features, and reads chapters.json + captions.json. It writes the chapter list and the full "Every caption" transcript as static HTML (readable without JS, indexable) and embeds the data as JSON for website/assets/js/tour.js: looping clip with YouTube-style overlay controls (play, prev, next bottom-left; Autoplay next, speed 0.5x-2x and fullscreen bottom-right; a draggable seek line above them; hidden 5 s after the cursor stops moving and at once when it leaves, back on any movement), NN / total counter and chapter title below the video with the current caption under it, keys arrows/space/k/f, Autoplay next on by default (a clip plays once and the next chapter starts), captions synced to the clip, click a transcript line to seek, deep links #<video>/<chapter>. The site header (site.js) fades out 3 s after scrolling stops when the page is not at the top, and any scroll brings it back; it stays while hovered, focused or with the mobile menu open. Hero videos are not published; re-render a video and rebuild the site and the page follows. Videos with no render are skipped. The same build inserts each video's chapter clips (click-to-play, linked back to the tour) after the intro paragraph of the user-guide page named in tour.json (inject_clips); the repo's docs/ and the in-app copy stay free of media, so they never show broken video. docs/user_guide/hardware.md is the Hardware video's page; it links into the existing MIDI/Twister/OSC sections of performance_controls.md rather than repeating them.

    Publishing the site

    Videos and their posters are not on GitHub Pages: the build links them at MEDIA_URL (build_website.py, https://www.spaz.org/~gj/liquid-lsd-files, Apache with range requests) and writes them to <build>/tour/media/, which publish_site.sh copies to the server first with rsync -c over SSH (MEDIA_SSH; key login), so only changed videos upload. Captions (tour/captions/*.vtt) stay on the site, since browsers refuse cross-origin caption tracks. --media-url file://... previews a build locally. scripts/publish_site.sh builds the site and pushes it to greenjon/liquid-lsd-site (cloned next to this repo on first run); that repo's Actions workflow (website/deploy/pages.yml) deploys it to GitHub Pages at liquid-lsd.greenjon.com (SITE_HOST in build_website.py; the build writes CNAME and .nojekyll). The site repo holds no media since 2026-10-20 (its history was squashed then); --squash still resets its history to one commit. Pass --tours tours/out (or leave the default) to choose which render is published; check that you are not publishing draft renders.

    Each chapter also gets a .jpg thumbnail (a frame a few seconds into its clip, made with ffmpeg at site build time), used as the poster on the tour page and the docs clips.

    Landing page and the overview video

    website/data/landing.json names the hero video (overview) and the four featured chapters shown as "See it in action" cards on the landing page (slug = <video>/<chapter>, plus a one-line blurb). The cards are muted loops that play only while on screen; phones, reduced motion and data saver get thumbnails only. The hero video is the only full-length file published: the build re-encodes its hero.mp4 to 1080p30 H.264 (CRF 30, slow preset, cached in the gitignored tours/web-cache/, about 28 MB for the 6-minute draft) and copies it with its poster and .vtt captions to tour/media/<video>/. It loads on click (.video-facade) on both the landing page and the tour page.

    Which videos are stale

    scripts/render_tour.sh stamps <out>/<tour>/rendered_at.json (commit, dirty-tree and draft flags). scripts/tour_staleness.py compares each stamp with HEAD and lists the tours to re-render: it maps the widget keys a script aims at (target fields) to the Kotlin files that register them, then reports commits since the render that touched those files, the script itself or the tour renderer (tour/). Other commits under ui/, rendering/, shaders or defaults/ are counted as "maybe" because colors and layout change a video without touching a key. -v lists the commits and any keys it could not map (dynamic or very generic labels such as btn_Randomize are not tracked); --names prints only the stale tour names; --out points at a different render root. Videos rendered before stamping existed fall back to the video file's date. Weekly: run it, then render_tour.sh on the names it prints.
