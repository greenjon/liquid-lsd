# Fractal Flame Source

The Fractal Flame generator (`fractal_flame`, class `FlameSource`) is an evolving-genome source: a large parameter set, a GPU point renderer and a sampler that picks the next morph target. Math: Draves & Reckase, "The Fractal Flame Algorithm" (clean-room, paper only). Status: experimental, extracted like the stock sources but listed in `VisualSourceRegistry.EXPERIMENTAL_SOURCE_IDS`. Planning notes and measurements live in `.planning/flame-source-plan.md` and `.planning/flame-source-handoff.md`.

## Rendering (`FlameEngine`, OpenGL 3.3 core)

1. A ping-pong RGBA32F **state texture** (512x512, one IFS point per texel: x, y, colour, age).
2. **Iterate pass**: a fragment shader over the state texture picks an xform by weight, applies pre-affine, the pre-stage variations, the weighted variation slots and the post-affine, blends the colour index, and reseeds diverged points.
3. **Splat pass**: `GL_POINTS`, one vertex per point (state fetched with `texelFetch`), optional final xform, camera, then a Gaussian sprite additively blended into an fp16 density buffer that persists with `Decay`.
4. The folder's `shader.frag` is the **tone-map pass** `Renderer` binds (log density, toe, gamma, vibrancy). The engine overrides `uExposure` with `Exposure * n / rows` so the tier's point fraction and the governor do not change brightness; it is also multiplied by `FlameQualityTier.passExposure` (4 / passes) so the pass count does not either.

Cost is per point (about 3 ns each on the dev iGPU), not per pixel. The shared GLSL (`FlameEngine.COMMON`) holds the `vari()` switch (95 cases); ids are the variation numbers (the paper's 0-48, then the numbers of `.planning/flame-variations-spec.md`, 49-98) and index `FlameVariations.ALL`.

**Pre stage.** `Variation.pre` marks a variation that acts on the point after the pre-affine and before the xform's other variations (`pre_blur`, id 67). In `applyXf` the pre variations run first in slot order, each replacing the point with its own output (observed with JWildfire 9.00: `pre_spherical` at weight w gives `w * spherical(p)`); the other slots then add up on the result and the post-affine follows. An xform with only pre variations has an empty sum, so a pre variation is paired with a regular one (usually `linear`). The shader's `isPre` lists the pre ids; `FlameVariationsTest` keeps it in step with the table. `pre_blur` adds a random direction at a bell-shaped distance (sigma about 0.73 w) to the point (`FlamePreStageTest` checks its cloud against the observed distribution). Post-stage variations (`post_crop` ...) are not built yet.

**Reserved ids.** The table is index-addressed, so a variation that is not built keeps its id as a placeholder (`Variation.supported = false`): 50 super_shape, 65 lazysusan and 98 mobius are skipped for v1 (more parameters than a slot's four, or they alter the point rather than add to the output). A placeholder has no `case` (the switch falls through to linear), the id knob labels it "(unsupported)", the sampler gives it odds 0 and the importer lists its name in the preset notes when a file uses it with a non-zero weight. `FlameVariationsTest.glslCasesMatchTheTable` compares the case labels with the supported ids and the trailing `// name` comment with the table.

**Conventions for ids 49+.** Divisions, logs, square roots and powers that can see a bad input go through `sdiv`, `slog`, `ssqrt`, `spow` and `remT`, which return NaN, so the iteration loop discards the point on every driver instead of using a driver-dependent value. The loop's bad-value test is `abs(x) < 1e4` (the spec's 1e10 would let huge points through to be drawn off-screen), NaN included. `r2` carries a +1e-9 guard, so variations that scale the point by 1/r (flower, conic, scry) return (0,0) at the exact origin rather than NaN, a deviation the spec allows; those that do not multiply by the point (log, polar2, escher, cpow) use the exact r² and give NaN there. A variation with a "non-standard weight" (loonie, scry, whorl, flux) returns its finished output from its case instead of being multiplied by the weight again. edisc clamps X >= 1 and |x/X| <= 1 because single-precision rounding hits those bad values far more often than double. Parameter ranges are the spec's generator ranges, mirrored around the default when the default sits on an edge (so min < default < max always holds), and disc2's twist spans +-2 pi because the spec defines it beyond +-2 pi. The importer reads a parameter from `<name>_<label lower-cased>` and also under any alias prefix (`oscilloscope_*` for oscope).

## Genome as parameters (`FlameGenome`)

Parameters are built in Kotlin (not `meta.json`): 19 globals, six xforms and a final xform (weight, colour, speed, pre/post affine, four variation slots of id, weight and four normalised parameters `A`..`D`). Names are the preset keys (`X2 PreRot`, `X2 V1 Id`). `pack()` writes the `uXf` uniform array: weight-0 xforms are compacted, `Spin/Breathe/Warp/Drift` are applied, and each slot is `[idA, wA, idB, wB]` plus A's and B's parameters so a morph cross-weights two variation ids instead of sweeping through the ids in between. `FlameVariations.real/normalised` map the stored 0..1 values onto each variation's own range with 0.5 as the default.

## Morph and sampling

`DeckMorphController` owns A and B. A source that implements `GenomeMorph` picks its own targets (`sampleMorphTarget(from, target, random, strategy, fresh)`), keeps discrete parameters out of the lerp (`isDiscreteMorph`) and receives the live A/B/t (`onMorphUpdate`). `SamplerStrategy { RANDOM, MUTATE, POOL, BREED }` is `DeckMorphController.strategy` (default MUTATE, persisted as optional `DeckPresetDto.samplerStrategy`, written only when not MUTATE; null on load leaves the deck's setting alone). `forceRandomize` makes A a fresh genome (Random, or the Garden strategy) and B follows the strategy; `vetoTarget()` resamples the end the morph is heading to. `Zoom`, `CenterX` and `CenterY` are morph parameters: every target carries its framing (the gate verdict's for Random/Mutate/Breed, the offspring's own for Pool; `FlameSampler.mutate` skips them), so the camera drifts with the genome. The ZOOM macro knob drives the pinned `Magnify` multiplier (engine zoom = Zoom x Magnify) because macros write base values that the morph would overwrite. Each `DeckMorphSnapshot.origin` carries the genome's `FlameLineage` (parent names and tags) through promotions.

`FlameSampler` is pure: `mutate` (gaussian jitter on xform parameters, id swaps, xform birth/death), `random` (2-5 xforms, contractive pre-affines, 1-3 distinct variations from a weighted pool) and `breed` (whole-xform crossover, at least two active, then mutate). Final xform, camera, tone and modifier parameters are never part of a proposal. Only xform parameters are morph-enabled (`randomizeBase`); changing a parameter's default morph flag does not affect old saves, because `applyDto` restores the saved flag.

## Quality gate (`FlameProbe`, `FlameQuality`)

Every Random, Mutate and Breed candidate is run through the engine's own iterate shader on a hidden 128x128 state texture (40 passes, one 256 KB readback; GL state is saved and restored) and judged by `FlameQuality.analyse`: diverged (points reseeded), collapsed, line (covariance), exploded (too big to frame) or fog (every grid cell hit with near-uniform counts). `FlameSource.sampleMorphTarget` retries up to 8 times, then falls back (starter for a fresh request, no change for a drift). The same analysis frames the camera for a fresh genome, since Zoom/CenterX/CenterY are not part of the morph. Thresholds are constants in `FlameQuality`; `FlameProbeTest` prints the rejection rates, and `FLAME_SHEET=/tmp/sheet.png xvfb-run ./gradlew test --tests '*FlameProbeTest.contactSheet'` writes a contact sheet of random genomes (red border = rejected). Kept Pool picks skip the gate.

## Garden (`presets/Garden.kt`, `GardenThumbnails.kt`)

`Garden.keep(deck, ...)` saves the live deck (mid-morph: the nearer end, `FlameSource.nearerEndValues()`, swapped into the parameters just for the synchronous DTO build and restored after) through `PresetRepository.saveDeckPresetAsync` to `library/presets/garden/<slug>-NNNN.lsd` with tags `garden`, `gen:N` (youngest parent + 1) and `parent:<name>`, and writes `<name>.png` (256x144, blitted from the deck's output texture). `Garden.pool(sourceId)` reads the folder back (cached by modification time) for the Pool and Breed strategies; `GenomePool.pick` draws with weights: age rank 1..2 (newest 2x) times 3 for presets starred in the Sources browser (`BrowseFavorites` SRC keys, matched by absolute path via `Garden.favoritePaths()`). The browser lists the folder as a subfolder of Saved presets; no new browse root exists. `PresetListPanel` shows a preset's sibling png in its hover tooltip.

## Importer (`FlameImporter`, `presets/FlameImportOps.kt`)

`FlameImporter.parse(xml)` reads a `<flame>` or `<flames>` file (DOCTYPE refused, BOM stripped) into `Imported(values, palette, notes)`: xform weight/colour/`symmetry` (colour speed = (1 - symmetry) / 2), `coefs` and `post` affines decomposed into rotation, scales, shear and translation with the QR split that `FlameGenome.pack` inverts, up to three variations per xform by strongest weight (names and `<variation>_<param>` attributes follow the paper; `julian`, `juliascope`, `radial_blur`, `gaussian_blur` are aliases), the camera (Zoom = 2 * scale / height, centre, rotation), and the palette as 768 bytes (embedded in the preset: `FlameImporter.toPresetDto` writes it as base64 into the optional `DeckPresetDto.palette`; `Deck.toDto`/`applyDto` carry it through `FlameSource.customPalette`, which `FlameEngine.setPalette` uploads into the 256x1 palette texture; null = the procedural cosine palette, and a preset without a palette clears the deck's). The `Palette` parameter still shifts it cyclically. Weights above 2 are scaled together; out-of-range values are clamped and noted. Unknown variation attributes are detected heuristically for the notes only. The image's y axis is taken to point down: the importer sets the camera parameter `FlipY` (engine: `p.y *= uFlipY` after the camera rotation in the splat vertex shader), it does not conjugate the genome, which would change flames whose variations are not reflection-symmetric. `Options.transposed` (off) reads `coefs` the other way and `Options.flipRotation` (off) turns `rotate` the other way; both defaults and `FlipY` were checked against reference renders of `rings2-1.flame` (ring centre) and `blob-2.flame` (rotated, off-centre, asymmetric: only the unflipped rotation puts the burst in the right place and the transposed reading gives straighter rays than the reference). `FlameProbeTest.importerConventionSheet` (env `FLAME_IMPORT_SHEET`, `FLAME_IMPORT_FILE`) draws a file under the four option combinations for comparison with a reference render. Parameter ranges are deliberately wide so wild flames import unclamped (translations +-10, scales/shears +-4, slot weights -4..4, Zoom 0.01-32, centre +-16, Julia power -20..20); `FlameSampler.mutate` caps the range used for its jitter at 4 and lets an existing larger pre-scale stand, so drift behaves as before. All continuous parameters are stored normalised (0..1 or -1..1, angles in radians) so the UI shows 0..100 / -100..100 / -180..180; `FlameUnits.of(name)` holds the per-parameter map (linear, `Exponential` with 0.5 = neutral for zoom-like values, `Neutral` piecewise for Breathe/Warp) and every consumer (engine `v()`, `FlameGenome.pack`, `FlameSource.setupUniforms`, importer `put`, sampler) converts to real units at the boundary; `FlameSampler.mutate/random/breed` take and return stored values but work in real units inside. `FlameUnitsTest.everyContinuousParameterIsNormalised` fails for any new parameter that is not 0..1, -1..1, an angle or discrete. `Softness` (the `uSize` of the splat point sprite, 1-10, default 3) is a per-flame look parameter; the engine multiplies exposure by `(3 / Softness)^2` so the mean density stays put. The quality tier no longer has a kernel. The importer sets `Softness` to twice the file's filter radius scaled to a 1080 px deck (`IMPORT_DECK_HEIGHT`, clamped 3-10) `Toe` to 0 (the toe is an absolute threshold on decay-normalised density, so on sparse imports it removes nearly everything; Sharpness above about 3 shrinks soft sprites to a core, which defeats Softness) and `Decay` to `IMPORT_DECAY` (0.85): the originals assume millions of samples per image, and the in-view hit count is the limit (rings2-1: about 3% of points land in view at the file's camera, so an HD deck gets ~0.1 effective samples per pixel against the original's ~10; decay cannot close that gap, hence the `Smooth` blur below). `Smooth` (0-1, 0 = off, imports set `IMPORT_SMOOTH` 0.5) is a density-estimation blur in the tone-map shader (`estimate()`): while Smooth > 0 the engine calls `glGenerateMipmap` on the density texture (min filter LINEAR_MIPMAP_LINEAR, set when the FBO is created; the shader reads level 0 explicitly with `textureLod` otherwise), and the shader walks mip levels 5 down to 0, mixing each finer level in with `smoothstep(0, 3*Smooth, a*(1-Decay)*uNorm)` of its own density. Dense pixels end up at level 0 (sharp), sparse ones at the finest level that is dense enough. Mips preserve the mean, so total light is kept; the blur runs on the raw density before Toe and the log. `uNorm` is the same factor the engine folds into `uExposure` (n/rows, `passExposure`, `(3/Softness)^2`), so the threshold does not move with the quality tier, the governor or Softness. Cost: mip generation plus up to 6 fetches per pixel, only while Smooth > 0; the threshold constant 3 is tuned by eye. `FlameImportOps.importFile` writes one preset per flame into `library/presets/imported-flames/` (never overwriting). Entry point: Sources browser `...` menu, *Import Flame...*.

## Offline curator (`tools/FlameCurator.kt`, `FlameViability`, `FlameAesthetics`)

Builds the shipped flame library (no third-party genomes: the importer's input is user-supplied only). `./gradlew curateFlames -Pargs="--candidates 20000 --minutes 45 --out build/curated-flames"` needs a GL 3.3 context and runs a quality-diversity (MAP-Elites) search: proposals are fresh `FlameSampler.random` or mutate/breed of archive elites, and each passes a funnel of filters: `FlameViability` (numbers only: three or more active xforms, no xform over 97% of the weight, not all pre-affines singular, not all linear-only and expanding; expanding affines alone are fine because variations fold space), the `FlameProbe` gate, a real 512x288 render (14 frames, Decay 0.85, Smooth 0.3, governor off, Medium tier) scored by `FlameAesthetics.score`, and four re-renders with the handles pushed (Spin +-0.8, Warp 0.3, Breathe 0.85) whose worst score blends into the final one. `FlameAesthetics` is pure maths on an RGBA readback: coverage, luma entropy, Sobel edge density at two scales, hue spread and dominance, plateau share, clipping, symmetry; the score is a geometric mean of trapezoid bands, so one bad axis sinks it (all ranges are guesses tuned on contact sheets). The archive cell is fill x structure x hue x symmetry (525 cells, `--per-cell` elites each). Output: `curated-NNNN.lsd` + thumbnail, `metrics.csv` and `sheet.html`: click a flame to cycle keeper, seed (breeding stock), reject, then Download `decisions.txt` and run `--apply <dir> decisions.txt` (deletes rejects, adds the `seed` tag to seeds; `--sheet <dir>` rebuilds an older sheet). Seeds are skipped by the Pool strategy (`Garden.SEED_TAG`, filtered in `FlameSource.sampleMorphTarget`) but Breed draws them, since breeding copies whole xforms and not palette, tone or camera. `--seed-dir <dir> --out <other>` starts a new search from the picks: most parents are the seeds and only 8% of proposals are fresh random, so the search follows the user's taste. Render resolution matters: the Smooth blur works in absolute mip levels, so a small render shows blocky plates that the app does not.

## Auto-governor (`FlameGovernor`)

Fed the engine's GPU timestamp samples, it scales the iterated and drawn rows (the quality tier's point count stays the ceiling) to hold the `flameBudgetMs` preference (default 3 ms, 0 = off): smoothed time, proportional steps, shed fast and recover slowly.

## Tests

`FlameGenomeTest`, `FlameVariationsTest` (Kotlin mirror of the deterministic formulas against hand-derived pairs and every deterministic pair of the spec), `FlameShaderValuesTest` (GL: the real `vari()` on spec pairs), `FlameSamplerTest`, `FlameQualityTest`, `FlameGovernorTest`, `FlameEditorLayoutTest`, `GardenTest`, and the GL tests `FlameShaderCompileTest` and `FlameProbeTest` (skipped without a GL context; run them under `xvfb-run`). GL tests that draw must share one context per JVM: `Geometry` caches its fullscreen-quad VAO.

## Gotchas

- Files in `library/sources/<id>/` are extracted once and never overwritten: delete the folder after changing a bundled source's resources.
- A saved session or preset keeps each parameter's saved `randomizeBase` flag, so old saves do not pick up a changed morph default; re-add the source.
- `gradlew run` does not forward `-D` flags; the engine's measuring switches are env vars (`FLAME_N`, `FLAME_DENSITY`, `FLAME_SKIP`).

**Shipping the curated set.** The flames you keep after `--apply` are copied into `defaults/presets/garden/curated/` (`.lsd` plus thumbnail); `PrepareDefaultAssetsTask` adds everything under `defaults/presets/garden/` to the bundled presets manifest as `garden/curated/<name>`; `FileSystemManager.ensureDefaultLibrary` extracts them into `library/presets/garden/curated/` on first run without overwriting anything. `Garden.pool` walks its folder recursively, so Pool and Breed use them immediately. The set (158 flames from the second review round, 2026-10-12) is about 16 MB of resources.
