# Web Subsystem & Broadcast Protocol

This document provides a technical specification for Liquid LSD's browser-based WebGL2 visualizer, live WebSocket broadcast relay, and desktop-to-web synchronization architecture.

---

## 1. System Topology & Architecture

Liquid LSD's web subsystem enables zero-latency live visual streaming without video transcoding by transmitting lightweight mathematical state representations over WebSockets to client-side WebGL2 renderers.

```
┌──────────────────────────────────────────────────────────────┐
│ DESKTOP APPLICATION                                          │
│                                                              │
│  Mixer / Deck Engine ──► WebPresetSerializer (JSON)          │
│                               │                              │
│                               ▼ (throttled, 5-60 Hz)         │
│  BroadcastEngine-IO Thread ──► java.net.http.WebSocket       │
└───────────────────────────────┬──────────────────────────────┘
                                │ WSS: ?role=broadcast&key=<token>
                                ▼
┌──────────────────────────────────────────────────────────────┐
│ NODE.JS RELAY SERVER (server/server.js)                      │
│                                                              │
│  - Authentication & Role Verification                        │
│  - Active Broadcaster Arbitration                            │
│  - Merged State Cache (late joiners get current state)       │
│  - Low-Latency Fan-Out Distribution                          │
└───────────────────────────────┬──────────────────────────────┘
                                │ WSS: ?role=viewer
                                ▼
┌──────────────────────────────────────────────────────────────┐
│ BROWSER CLIENT (web/)                                        │
│                                                              │
│  - Autopilot Playlist Manager (autopilot.js)                 │
│  - Web Audio DSP Graph & Beat Tracker (dsp.js)               │
│  - Beat-Clock Extrapolation (renderer.js)                    │
│  - WebGL2 Multi-Pass Pipeline & CRT Post-Processing          │
└──────────────────────────────────────────────────────────────┘
```

## 2. WebSocket Wire Protocol (v2)

The relay server and browser clients exchange compact JSON messages. Every `state_full` carries `"v": 2`; a client that speaks another version ignores it (and the deltas that follow, until a full snapshot of its version arrives). Values on the wire are the desktop's **evaluated** parameter values, rounded to 4 decimals, so the browser runs no modulators in live mode and matches the desktop exactly.

### Message Types

#### 1. Full State Snapshot (`state_full`)
Sent when the broadcaster connects, when a preset or setlist changes, and by the relay to a viewer joining mid-session (built from the relay's merged state, not the broadcaster's last snapshot).

```json
{
  "type": "state_full",
  "v": 2,
  "clock": { "beats": 812.4, "bpm": 126.0 },
  "preset": {
    "deckA": {
      "source": "dynamic_spiral",
      "params": { "MaxPoints": 500.0, "Scale": 0.5, "HueOffset": 0.2 },
      "viewZoom": 1.0, "viewRotateZ": 0.0, "globalAlpha": 1.0,
      "fx": {
        "0": { "id": "feedback", "dryWet": 1.0, "params": { "fbDecay": 0.65, "fbGain": 0.48 } },
        "1": null,
        "2": null
      },
      "fxDryWet": 1.0
    },
    "deckB": { "empty": true },
    "deckBG": { "empty": true },
    "mixer": {
      "balance": 0.0, "alpha": 1.0, "levelA": 1.0, "levelB": 1.0, "levelBG": 1.0,
      "transition": "linear_crossfade", "transitionParams": {},
      "fx": { "0": null, "1": null, "2": null }, "fxDryWet": 1.0
    }
  }
}
```

- **`params`** is keyed by the exact parameter name: the ISF input `NAME` the shader uniform uses (Mandala uses its own names, e.g. `Hue Offset`). The browser looks the name up in the source's ISF header.
- **`fx`** is an object keyed `"0"`..`"2"`, not an array, so a delta can address one slot parameter. An empty slot is `null`. `dryWet` is the *effective* wet amount (zero for a disabled slot, scaled by the desktop's FX dip). `fxDryWet` is the effective chain wet. The master chain is `mixer.fx` / `mixer.fxDryWet`.
- **`balance`** is the crossfader mapped to 0..1 (the transition's `progress`). `transition` is a transition id from `web/catalog.json`; unknown ids fall back to `linear_crossfade`.
- **`mandala`** (Mandala decks only) holds the shader-ready uniforms (`uL1`..`uL4` already normalised, `uA`..`uD` from the selected recipe, `uThickness`, `uHueOffset`, `uHueSweep`, `uDepth`, `uMaxR`), because the browser has no recipe table.
- **`broadcaster`** (optional string, at most 40 characters) is the broadcaster's name from `BroadcastPreferences.broadcasterName`, for the web TV's LIVE title card. It rides inside `preset` so the relay's merged state and the deltas carry it with no relay change (a delta's `null` clears it); clients that do not know it ignore it, so the protocol stays v2.
- **`empty: true`** marks an empty deck; a source the web cannot draw (external video) is sent with an id the catalog does not know and renders as nothing.

#### 2. Throttled Delta Update (`state_delta`)
Streamed at `BroadcastPreferences.targetFps` (5-60 Hz). `patch` is a recursive diff against the last state sent: only changed keys appear, and `null` means the key was removed or the slot emptied. An empty `patch` is a once-a-second heartbeat that only carries the clock.

```json
{
  "type": "state_delta",
  "clock": { "beats": 812.9, "bpm": 126.0 },
  "patch": {
    "mixer": { "balance": 0.52 },
    "deckA": { "fx": { "0": { "params": { "fbDecay": 0.7 } } } }
  }
}
```

#### 3. Broadcaster Handshake (`broadcaster_online` / `broadcaster_offline`)
Dispatched by the relay server to all connected viewers when the desktop broadcaster connects or disconnects:
- `broadcaster_online`: Viewers smoothly transition from Autopilot mode to the live broadcaster state, and `#source-badge` says `LIVE SHOW`, and the station badge keeps the channel.
- `broadcaster_offline`: Viewers smoothly fade back to local autonomous Autopilot playlist cycles.

### Relay state (`server/state.js`)
The relay keeps the broadcast state merged: each `state_full` replaces it, each `state_delta` is applied to it (a `null` deletes the key). A viewer that joins mid-session is sent a `state_full` built from it, with `clock.beats` advanced by the time since it was recorded, so it starts on the right beat. Messages of another protocol version are relayed but never cached. Tests: `cd server && npm test` (no `ws` needed).

## 3. Beat Clock

Every message carries `clock: {beats, bpm}`, the desktop's synchronised beat count and tempo at the moment of sending. The browser stores it with the local `performance.now()` at arrival and extrapolates (`beats + elapsed * bpm / 60`) for every `lfo`/`beatSine` modulator and any web-side evaluation, so in live mode it needs no beat detection of its own. Network latency (tens of milliseconds) is not compensated; the once-a-second heartbeat keeps drift from accumulating. Outside a live broadcast the client tracks the radio stream's own beat (below), so beat-synced modulators land on the music's beats there too.

**Standalone beat tracking (`web/onset-worklet.js`, `web/beattrack.js`).** An AudioWorklet computes onsets at audio rate, one set per 10 ms, so their timing does not depend on the frame rate. Each is stamped with the `performance.now()` time it is *heard* (`AudioContext.getOutputTimestamp`), so output latency is compensated. It measures two things, because each does one job better: a **phase envelope** (rise in log energy of the bass below 150 Hz, weighted double, plus the full signal) and three **tempo bands** (rise in RMS level through the same 150 Hz low pass, 1 kHz band pass and 5 kHz high pass as the desktop's `BeatTrackerEngine`). Tempo alone improved with the bands; using them for phase too lowered the on-beat share on 18 of 43 mixes.

`BeatTracker` keeps 8 s and, every 250 ms, estimates the tempo the way the desktop does (see [Beat Sync](beat_sync.md)): each band in units of its own mean rise, autocorrelation over a 4 s window weighted to the newest, a comb over each lag's first 4 multiples under a log-normal prior one octave wide around 120 BPM (70-180 BPM), a check of where the accents fall among the 6 strongest peaks with a bonus for the tempo already held, and unwrapping to the half period while its accents reach 55%. The unwrap limit is 180 BPM, not the desktop's 165, so drum and bass reads 174. The desktop's tempo inertia is **not** ported: here it fights the fine-tuning below and took agreement with hand readings from 88% to 34%. Without worklet bands (no AudioWorklet support) the per-frame onset strength feeds the same estimator.

It then fine-tunes the period by +-2% to the one whose comb peaks highest and finds the phase with a comb filter on the phase envelope. Confidence is how far the best phase stands above the average, and is zero unless the older and newer halves of the window agree on the grid.

`BeatClock` drives a `BeatFlywheel` (the live-mode flywheel) from those results, in three steps. A tempo must hold within 3% for 20 readings (about 5 s, `TEMPO_SETTLE`) before the clock follows it or trusts the phase: music holds, talk does not, and without this rule the clock changed speed 14 times a minute on spoken word. Once settled it runs at the tracker's tempo even when the phase is unsure, so a section with no clear beat does not coast at a stale tempo. Confident readings then anchor the phase: two in a row must agree, a small backward error is absorbed by coasting, and a jump (over a quarter beat) must hold for 8 readings (about 2 s, `JUMP_CONFIRM`) and moves *forward*, so the beat count never runs backward. While a small backward correction is being absorbed, `BeatFlywheel.read` runs at 80% of the tempo until the true beat catches up; at full tempo, as the desktop's `getSynchronizedTotalBeats` still does, the output stays ahead until the next forward correction, which left kicks up to 130 ms off. Live mode gets this too. `cvState.beatLocked` is true while a confident estimate arrived in the last 4 s.

| Offline, real code | Before | After |
| :--- | ---: | ---: |
| Hand readings from Mixxx on one 100 min mix: right or an octave off | 45% | 89% |
| 596 tracks against BPM tags (a second opinion): with octaves (the desktop: 83%) | 61% | 81% |
| 43 mixes, 45.5 h: time locked | 49% | 79% |
| 43 mixes: phase jumps per minute | 1.05 | 0.45 |
| 43 mixes: tempo moves over 3% per minute | 0.84 | 0.63 |
| 43 mixes: share of onsets on the beat as viewers get it (chance 25%; better on 39, worse on 2) | 32.2% | 34.0% |
| 8 h of spoken word: time locked | 22% | 12% |
| `analyse()` on the dev machine, main thread, four times a second | 3.2 ms | 5.6 ms |

Known limits: beat placement improves far less than tempo, lock and jumps, and on dense breakbeats the on-beat share stays near chance (a 2.4 h drum and bass mix reads 174 but locks 50% of the time and scores 27%). A new tempo takes about 5 s longer to reach the clock. The tracks and mixes were also used to choose between designs, so these numbers are somewhat optimistic.

Checks: `node --test web/tools/beattrack.test.mjs` (synthetic envelopes: tempos, off-beat hats, missing kicks, tempo changes, syncopation, noise, clock lock, settling, jump confirmation); `node web/checks/beat_check.mjs [bpm ...]` (a synthetic track through the real worklet in headless Firefox; fails unless every kick lands within 30 ms of a beat); and `node web/checks/tempo_report.mjs tags|truth|mixes FILE [--web DIR]` (a measuring tool: the real code offline over your own music, with `--web` pointing at a baseline checkout; hand readings for the mix above are in `.planning/tempo-truth-magical-bass-8.json`).

**The autopilot runs on this clock.** `settings.json` holds are in bars (`fgHoldBars` 16, `bgHoldBars` 32) and fades in beats (`fgFadeBeats` 4, `bgFadeBeats` 8). A change starts `FadeBeats` before the first bar line after the hold and finishes on it, so a new scene arrives on the bar. The next preset (with its chain and transition) is built during the hold, so the change is not delayed by fetching. Bar lines are every 4 beats of the clock's own count; the clock does not know where the music's bar starts (downbeat detection is not done).

**Song sections (`web/energy.js`).** `EnergyWatch` follows the low end (0.7 bass + 0.3 amp): a 1.5 s level against a 20 s reference (a running mean while the first 20 s fill). A *breakdown* is the level under 45% of the reference for 3 s (not during the first 20 s, and not in silence); the reference freezes during it (and while one is being confirmed, `holding`), so a *drop* is the level back above 85% of the pre-breakdown reference after at least 4 s (a shorter dip just ends the breakdown, and a calm scene it brought in leaves again at the next bar line). A breakdown longer than 60 s becomes the new normal, and so does the level over 1.6x the reference for 4 s (a louder song): the reference jumps to the 1.5 s level (`rebased`). The watcher lives inside auto gain (`AudioAgc.watch` in `dsp.js`, a port of the desktop `audio/SectionWatch.kt`), fed the fixed-scale levels; `dsp.js` publishes `cvState.section` and `cvState.drops` (and `cvState.energy`, the watcher itself, for tuning); on a breakdown the autopilot brings in a scene tagged `ambient` or `build` (from either playlist) at the next bar line and builds a `hard` / `bass-gated` scene, which cuts in on the drop with a half-beat crossfade through `settings.json` `dropTransition` (`laser_drop_flash`, kept out of the regular `transitions` rotation). HOLD overrides both. `node --test web/tools/energy.test.mjs`; `ui_check.mjs` drives a breakdown and a drop through the real page.

## 4. Browser-Side Web Audio DSP Graph (`dsp.js`)

In standalone web mode or Autopilot mode, the client performs real-time audio analysis on the Icecast stream (`https://radio.spaz.org:8060/radio.ogg`) via the Web Audio API:

```
Audio Element (Icecast stream)
     │
     ▼
createMediaElementSource() ──► GainNode (Rotary Volume Dial: V²) ──► AudioDestination
     │
     ├─► BiquadFilter (Lowpass 150Hz)  ─► AnalyserNode ─► RMS (audio_bass, audio_flux_bass)
     ├─► BiquadFilter (Bandpass ~1kHz) ─► AnalyserNode ─► RMS (audio_mid, audio_flux_mid)
     ├─► BiquadFilter (Bandpass 3.2kHz) ─► AnalyserNode ─► RMS (audio_himid, audio_flux_himid)
     ├─► BiquadFilter (Highpass 5kHz)  ─► AnalyserNode ─► RMS (audio_high, audio_flux_high)
     ├─► Broadband AnalyserNode ──────────────────────► RMS (audio_amp, audio_flux_amp)
     └─► AudioWorklet lsd-onset (10 ms onsets) ─► BeatTracker ─► BeatClock
                                                          (tempo, phase)  (totalBeats, bpm, beatLocked)
```

The `audio_*` values feed the modulators (`evaluator.js`) each frame; `totalBeats` and `bpm` drive every `lfo`/`seq`/`beatSine` modulator and the autopilot.

## 5. Desktop-to-Web Synchronization & Drift Tracking

To maintain 1:1 visual parity without manual dual-maintenance:
- **Authoritative Source**: Desktop GLSL shaders (`src/main/resources/shaders/`, `library/sources/`) and algorithmic Kotlin math files (`Evaluators.kt`, `WebPresetSerializer.kt`) are the sole sources of truth. (`icosa_h3` and `dynamic_spiral` are now pure ISF v2.0 shaders rather than Kotlin-backed generators — see `DECISIONS.md`'s "Standardization on Pure ISF v2.0 Shaders" — so their web ports are tracked as shader files, not algorithm files.)
- **Sync Manifest (`web/sync_manifest.json`)**: Authoritative mapping of desktop files to WebGL2 / ES module equivalents with tracked SHA-256 hashes.
- **Sync CLI Tool (`scripts/sync_web.py`)**:
  - `--check`: Compares actual files against manifest hashes and transpiled sources; fails with exit code 1 if drift exists.
  - `--apply`: Automatically transpiles desktop `#version 330 core` GLSL shaders to WebGL2 `#version 300 es` (`precision highp float;`).
  - `--mark-synced <target>`: Updates recorded hashes for verified manual Kotlin-to-JS algorithm ports.
- **Evaluator parity (`web/evaluator.js`)**: a port of `ModulatableParameter.evaluate()`, `Evaluators.kt` and `WaveformMath.kt`. It is checked by value, not by hash: `WebEvaluatorVectorsTest` runs the real desktop evaluator under simulated time and writes `web/tools/evaluator_vectors.json` (and fails when that file is stale, so a desktop change cannot go unnoticed); `node --test web/tools/evaluator.test.mjs` replays the vectors through the JS port. After changing desktop modulation, regenerate with `UPDATE_WEB_VECTORS=1 ./gradlew test --tests '*WebEvaluatorVectorsTest*'`, then fix the port until the node test passes. `beatPhase` and `sampleAndHold` are no longer registered in `CVRegistry`, so the desktop skips them and the web does not implement them.
- **ISF assets and the catalog**: `sync_web.py --apply` also copies `default_filters` and `default_transitions` into `web/shaders/fx/` and `web/shaders/transitions/` (same transpile: ES 3.00 header, uniform initialisers dropped) and regenerates `web/catalog.json`, the list of sources, filters and transitions the client can load. Ids are file stems, the same ids the desktop registries use. `--check` fails if the catalog is stale.
- **Content formats (`web/preset.js`, `web/mandala.js`)**: the autopilot reads the desktop's own formats. `web/presets/*.lsd` are `DeckPresetDto` files (a preset carries no FX); `parseDeckPreset` keeps each `ParameterDto` for `evaluator.js` and resolves `randomizeBase` once at load. FX come from `.lsdfxchain` (`FXChainDto`) files in `web/content/fxchains/` (copied from `defaults/fx_chains`) and `web/fxchains/` (web-authored, `web-*`; the rotation uses reactive `web-*` versions of the stock chains, generated in batch 7 of `gen_web_presets.py` before the stock chains got their own audio responses; no web chain strobes, for photosensitive viewers); transitions from `.lsdtrans` in `web/content/transitions/`. `web/catalog.json` lists all of them. A playlist line is `preset` or `preset | fxchain`; with no pin, `settings.json` `fxChains` rotates (empty = no FX) and `transitions` picks each crossfade's transition. Mandala is evaluated by `mandala.js`, a port of `Mandala.kt`'s recipe selection and uniforms over `web/mandala_recipes.json` (generated from `MandalaLibrary.kt`); `web/tools/mandala_vectors.json` pins the selection to the desktop. **Recipe roll**: a mandala preset whose `Recipe Select` has `randomizeBase` draws one recipe at load (`MandalaRecipes.rollRecipe`), uniformly over every recipe with a petal count in the `Lobes` range (or at the fixed `Lobes` count), and `parseDeckPreset` holds it by clearing the modulators on `Lobes` and `Recipe Select`, so the shape never switches on air. The autopilot loads the recipe table at startup and passes it in; the web presets that roll use `RECIPE_ROLL` in `gen_web_presets.py`, and `stock-mandala` gets it from `WEB_OVERRIDES` in `gen_stock_web_presets.py` (the desktop default spans only Lobes 3..8). **Photo gallery (`web/gallery.js`)**: source type `gallery` (`presets/spaz-gallery.lsd`, the first line of `default_bg.lsdplay`, so the TV starts with it; BG CHANGES defaults to `hold` in `ui.js` and `autopilot.js` so it stays). Like Mandala it is drawn outside the ISF graph (`renderDeck` in `renderer.js` calls `Gallery.render` into `pipe.clean`, then the deck's FX chain runs). One `Gallery` per renderer, so the photos carry on across background decks. `web/gallery.json` (`base` + `images`) lists the photos. **Curating** (`scripts/gallery_curate.py`): `download` copies every upload from the old radio page (its `imageURLs.ground`; the folder cannot be listed) into `gallery-curate/` and sets aside files that are not pictures (`_unreadable/`); `preview [port]` serves `web/` plus `/curate/` (`list.json` of what is left, the photos, `POST reject` moving one to `_rejected/`, `POST undo` moving the newest back), and `?gallery=curate` makes `gallery.js` read that list (re-read every 10 s), fetch each photo once in name order, show each for 4 beats with a name/progress line on top, and take `Delete`/`Backspace` (reject the top photo), `U` (undo) and `.` (next now); `build` writes what is left to `web/gallery/` (1024 px JPEG q85, EXIF-rotated, first GIF frame, ASCII names) and `web/gallery.json` with base `gallery/`. `export DIR [SIDE]` writes the built gallery at phone size (768 px default, JPEG q80) to `DIR/gallery/` + `DIR/gallery.json`: the Spaz Radio app's `scripts/sync_visuals.sh` runs it, so the app bundles the photos (its WebView loads nothing from the network; content updates carry no photos). `gallery-curate/`, `web/gallery/` and `web/gallery.json` are in `.gitignore`; `publish_web_tv.sh` uploads the working tree, so they reach spaz.org/tv. Until the first `build`, the published `gallery.json` is the 200 oldest uploads loaded straight from `spaz.org/images/ground/` (which sends `Access-Control-Allow-Origin: *`). `sw.js` keeps the newest 60 photos it served in their own cache (`lsd-tv-photos`, network first, the kept copy offline) and leaves `/curate/` to the browser cache; offline, after two failed photos, `Gallery.useKeptPhotos` switches the list to the kept ones and the `online` event restores the full list. Up to 8 photos on the GPU (scaled to 1024 px, mipmapped), 3 fetched at a time at first, then one every 20 s replacing the most-shown one off screen (the same 20 s tick fetches the list again if it failed, or starts over when every photo failed before one arrived, so a bad start recovers); up to 4 layers on screen, oldest first, premultiplied alpha, soft edges. Motion runs on a smooth beat clock (`dt * bpm / 60`), never the heard beat count (which can jump); a new photo comes in on a beat crossing every 2-8 beats (a beat late when the beat stands still). It has no parameters, so `validate_content.mjs` knows `gallery` and the rotation's reactivity gate skips it. The full render check settles it 7 s (the photos come from spaz.org). Validate authored content with `node --test web/tools/content.test.mjs` (`validate_content.mjs` checks ids, parameter names against the shader headers, ParameterDto fields and modulators; this includes the desktop's stock chains and transitions copied into `web/content/`, so a stock chain naming a parameter its effect no longer has fails the test, where the desktop would silently ignore it). `node web/checks/gpu_bench.mjs [WxH ...]` times every source on this machine's GPU (`gl.finish()` per frame, so the throttled headless frame timer does not matter).
- **Auto gain, REACT and the desktop Audio Response**: `web/dsp.js` ports the desktop `AudioAgc` (each band over its 20 s mean times `SCALE`, the references frozen while the section watch holds a breakdown and jumped on a new normal, a fresh start after 2 s of silence, divisor floor 0.02; `bandSignals(rms, prev, divisors)`), so `cvState.audio_*` match the desktop's at any stream level, and a breakdown reads quiet. `audio_flux_*` are hits: `FrameTransient` compares each frame's level with the level about 11.6 ms ago and `TransientGate` scores the rise against the last second's rises, the same gate as the desktop (`web/tools/transient_vectors.json`, `node --test web/tools/transient.test.mjs`); the hit is held 34 ms like the desktop's, and `hitSignals` sizes it with `HitScale` against the band's recent strong hits, as the desktop does. A kick's raw peak stays within 20% between 30 and 144 fps. `AudioAgc.energy(band)` gives the per-band section signals. `WebAudioAgcVectorsTest` (desktop) writes `web/tools/agc_vectors.json`; `node --test web/tools/beatclock.test.mjs` replays it, so desktop changes cannot drift from the port. The detectors keep the fixed 0.25 / 0.05 / 0.1 scales, as on the desktop: `cvState.raw` (`audio_amp`, `audio_bass`, `audio_flux_amp`) feeds the fallback beat envelope and the no-signal check (and the section watch gets the same fixed-scale levels), since auto gain would lift a breakdown or a dead stream. Then both scale the signals before any modulator reads them and clamp to 0..1 (web: `renderer.js` multiplies `evalCtx.cv` by `viewerState.react`; desktop: `AudioEngine.response`), so `web/evaluator.js` has no reactivity input of its own. REACT 100% = Response 100%. `node --test web/tools/beatclock.test.mjs` covers the port.
- **Stock scenes (`scripts/gen_stock_web_presets.py`)**: `web/presets/stock-<source>.lsd` are generated from the desktop's `stock_defaults/sources/<id>.json`. The sparse file is completed into full ParameterDtos (baseValue from the shader's DEFAULT, or the middle of the range; `randomizeBase` rolls it at every load), modulators (including bypassed alternates) are copied as they are, and tags come from the active modulators (`bass`, `kick`, `mid`, `amp`, `high`, `bar`) plus `fullframe` / `sparse`. Sources with no active modulator (Fluid Ink) or not in the catalog (Fractal Flame) are skipped. Re-run it after a stock default changes; the rotation gate and `content.test.mjs` guard the result.
- **Authoring web presets (`scripts/gen_web_presets.py`)**: the `web-*` presets and chains are generated from short definitions (the generated files are the source of truth once committed; hand edits are fine). Recipes: `pulse(beats, depth)` is an envelope that peaks on the beat; `lfo(beats, depth, wave)` is a beat-synced LFO (period in beats; 16 = four bars); `kick`/`hat` follow `audio_flux_bass`/`audio_flux_high`; `bass`/`mid`/`high`/`amp` follow the band levels with attack/decay smoothing; `gate(source, threshold, depth)` stays silent until the signal passes the threshold. **A gate only works on a parameter whose base is its minimum** (0 = "off"): below the threshold the amount goes negative and clamps at the minimum, so on any other base the silent value dips below base. Parameters in the shaders are normalised 0..1 or -1..1, so ADD depths are fractions of the range (half the range on bipolar parameters); `lfo` on a unipolar parameter sweeps base..base+depth. Tag a preset with the behaviours it promises (`beat`, `bar`, `bass`, `kick`, `mid`, `high`, `amp`, `bass-gated`); `node --test web/tools/reactivity.test.mjs` verifies each tag is backed by a parameter that moves. The same test is the **rotation gate**: every preset in a playlist and every chain in `settings.json` `fxChains` or a playlist pin must move with some audio signal or with the beat (a beat-synced LFO counts), so nothing deaf reaches the web TV. It also fails on any modulator on a **rate parameter** (a name ending in `Speed`, `Spin` or `Rate`) that the shader does not integrate: `TIME * Speed` moves the phase by `TIME` times the change, so after a few minutes on air even a small wobble jumps the picture every frame. Every stock source and filter now integrates its rates (`LSD_PHASES`, see [rendering.md](rendering.md#6-integrated-phases-lsd_phases)), so the check only bites on a new shader that multiplies by `TIME`. Each source has a groove, a hard and an ambient preset (ambient ones go in the BG playlist). Presets of sources that fill the frame with colour are tagged `fullframe` (`FULL_FRAME_SOURCES` in the generator); `web/pairing.js` makes the autopilot skip chains with a feedback or bloom slot for them, since those wash a full frame out to one flat colour, and presets of sources drawn as fine dots or thin lines (`SPARSE_SOURCES`: dynamic_spiral, harmonograph) are tagged `sparse` and skip chains with pixelate, halftone, polar_tunnel, luma_displace or directional_blur, which average or smear them away to black; and `render_check` picks chains the same way; `content.test.mjs` validates names and ranges, and `node web/checks/render_check.mjs` renders every preset (scene at the PNGs: sources differ in how much they show at default settings; `hyper_slice` blows out under strong feedback, `gyroid_hyperspace` is black unless Brightness/Zoom are raised, a solid gyroid surface is mostly black). `RC_EXTRA=specs.json RC_ONLY=name` renders ad-hoc scenes, and `RC_LOUD=1` adds a `<name>_loud` frame per preset with the audio signals held high, to compare against the silent frame.
- **Render graph (`web/isf.js`, `web/graph.js`)**: `isf.js` wraps ISF source into GLSL ES 3.00 (a port of `ISFParser.buildGLSLFragmentShader`) and runs multi-pass shaders (`PASSES`, `TARGET`, `PERSISTENT` ping-pong, `FLOAT`, `$WIDTH`/`$HEIGHT` expressions). `graph.js` is `Renderer.renderDeck`/`renderMixer`: deck source, 3-slot FX chain, transition, composite over BG, master FX chain. Assets compile lazily on first use (`Library`), and a not-yet-loaded effect is skipped for those frames. Mandala is the only source drawn outside the graph. A source's last pass is drawn with `blendFuncSeparate(SRC_ALPHA, ONE_MINUS_SRC_ALPHA, ONE, ONE_MINUS_SRC_ALPHA)` over the cleared target (`renderISF(..., {premultiply: true})`), so it is stored as colour x alpha with alpha as written, the same as the desktop `Renderer`; the mixer and FX expect that. Black-is-transparent sources write straight colour (`c / a`, `a`), so without it their dark areas came out bright (the washed-out web TV of 2026-10-26 to 11-01). Intermediate passes are not blended, so feedback buffers keep raw values. `IMPORTED` assets are not supported (nothing bundled uses them). Built-in scalars (`time`, `mouse`, ...) skip a name the shader uses for a texture, and a `MIN` above `MAX` is read as swapped (`paramSpec`), as on the desktop.
- **Shader audio textures (`web/audiotex.js`)**: the web side of [rendering.md section 7](rendering.md#7-audio-inputs-and-third-party-compatibility). `SpectrumAnalyzer` ports `SpectrumAnalyzer.kt` (1024-sample Hann FFT, 512 bins, full-scale sine = 1, -80..0 dB onto 0..1, 0.08 s release); `dsp.js` gives it the newest 1024 samples from its own `AnalyserNode` (off the analysis input, so radio, microphone and the embed feed all reach it) every frame, with the samples that passed since the last frame as the release time, and copies the newest 512 samples as the waveform into `audioFrame`. `AudioTextures` (in `renderer.js`'s `ctx.audio`, refreshed once per frame) holds the stacked 512x2 texture for `audioFFT` / `iChannel0` and the 512x1 spectrum and waveform for ISF `audioFFT` / `audio` inputs; `renderISF` binds them after the image and pass textures (an input named `audioFFT` gets the 1-row one). The textures are R16F (filterable in core WebGL2). Checked by value: `WebSpectrumVectorsTest` writes `web/tools/spectrum_vectors.json` and `node --test web/tools/audiotex.test.mjs` replays it. - **ROLL, AUTO ROLL, BACKGROUND, EFFECTS, FOLLOW MUSIC, channel skip (`autopilot.js`, `ui.js`)**: `buildDeck` keeps the stored preset (`deck.raw`) and `applyChain` the stored chain (`deck.chainDto`). `rollScene()` re-settles both (`parseDeckPreset` / `parseFxChain`, so Mandala's recipe roll applies) and glides every changed base from `tickAutopilot` (`tickRoll`, smoothstep) to the next bar line at least 2 beats away; stepped inputs (`paramSpec(input).steps > 1`, looked up through `setSteppedLookup`, which `renderer.js` registers over the loaded ISF headers; Mandala's Lobes / Recipe Select) snap at the end. The deck is changed in place, so its history entry keeps the rolled values; `finishRoll()` lands a roll at once before a crossfade or FX change. `setAutoRollBars(n)` rolls every n bars of a hold (`planAutoRoll` from the hold's start; skipped within a bar of a scene change). `setEffects(false)` strips the chains on air and queued (`deck.fxStripped`), `pickChain` is never consulted while off, and `setEffects(true)` / `tuneChannel` re-chain stripped decks. `setFollowMusic(false)` skips `followSections` and the tempo weighting. `setBackgroundMode('scenes' | 'hold' | 'off')` (default `hold`): `hold` never starts a timed change; `off` dips out over 4 beats to state `off` with `deckBG = null` (the mixer gets the clean texture), and back on, the next background fades in. `stepBackground(dir)` builds the next line (superseding token `bgPrepareToken`) and dips over 2 beats. Skips are a `Set` of preset names (`setSkipped`, stored by `ui.js` as `lsd.skipped` and pruned to the playlist at the first `lsd-now-showing`): `playable(line)` = `runnable(line)` (heavy / reduced motion) and not skipped, so the rotation, `J`, CH up/down and `pickLine` all skip them; `tuneTo(n)` (digits, the SKIPPED page) only needs `runnable`. `toggleSkip()` refuses below `SKIP_FLOOR` (8) playable channels. Viewer settings live in `localStorage` as `lsd.autoRoll`, `lsd.bgMode`, `lsd.effects`, `lsd.follow`. `node --test web/tools/viewer_controls.test.mjs` runs the real autopilot over the shipped content (a file-backed `fetch`); `ui_check.mjs` drives the buttons, keys, menu rows and the SKIPPED page.
- **Variation spans (`scripts/gen_web_presets.py`)**: every curated web-* preset and chain parameter is `randomizeBase` over `base ± VARIATION` (15% of the input's range; hues 30%), clamped to the range, except stepped inputs, `NO_ROLL` (feedback decay / gain / mode / kaleido), gated parameters and bases at either end of the range (hues excepted). Also held: selector-named floats without a STEP (`SELECTOR_NAME`: `SurfaceType`, `PlateShape`) and framing (`FRAMING_NAME`: Zoom, distance, FOV). No parameter moves more than half its distance from 0 (bipolar) or its minimum, so small values don't triple and a speed never stops or reverses; and on `SPARSE_SOURCES` and Mandala the size / glow / thickness / width / scale parameters roll upward only (fine dots and thin lines go black otherwise). Elsewhere brightness-type parameters (`BRIGHT_WORDS`: bright, glow, gain, exposure, intensity, bloom, contrast) roll downward only, so a roll is never brighter than the tuned look on them. `baseMin` / `baseMax` are the roll span only: modulation still scales by the shader's own MIN / MAX (`evaluateParameter`). `render_check.mjs` renders presets at their tuned values (`roll: 'base'`), so it stays repeatable; `RC_ROLL=n` adds n on-air rolls per preset (`_roll1`..) and prints how many left the brightness band, a sample of the spans' health that does not fail the check.
- **Headless checks (`web/checks/`)**: `node web/checks/shader_check.mjs` compiles every catalog shader in headless Firefox; `node web/checks/render_check.mjs [outDir]` drives the real app through every source, filter, transition and bundled preset, writes PNGs, and fails on blank frames, console errors or GL errors. Both need only `firefox` and `node`; software GL is fine.
- **Beat and audio parity (`web/beatclock.js`, `web/dsp.js`)**: live mode runs `BeatFlywheel` on the wire clock (`getSynchronizedTotalBeats` semantics plus blending of each anchor against network jitter); standalone runs `BeatClock` on the stream's tracked beat (section 3). `dsp.js` publishes `audio_*` and `audio_flux_*` with the desktop's scaling (`AudioEngine`: RMS / 0.25, band flux / 0.05, amp flux = (2 bass + 0.8 mid + 0.3 high flux) / 0.1). Beat tracking only runs from the radio stream, so it only matters standalone.
- **Continuous Integration**: Gradle task `./gradlew checkWebSync` and JVM unit test `WebSyncTest.kt` guard against drift on every build.

## 6. Publishing the Web TV

The web TV is served at **https://spaz.org/tv/**: Apache on spaz.org has `Alias /tv /www/spaz/htdocs/lsd-relay/public`, a folder `gj` can write over SSH (key login). `scripts/publish_web_tv.sh` rsyncs `web/` there (checksums, so only changed files go; `web/checks/` and `web/tools/` stay behind). `--dry-run` shows the changes, `--delete` also removes server files that are no longer in `web/` (older deployments left prototype shaders and desktop presets there). ## 6b. Embed Mode (`?embed`)

`index.html?embed` is the web TV as a component, built for Spaz Radio's Android WebView (plan: `.planning/spazradio-embed-plan.md`). `embedmode.js` exports the flag; it implies the kiosk layout and adds `body.embed` (`tv.css`: chrome hidden, `pointer-events: none` everywhere, so the host's panels own all touches).

- **Audio in:** `dsp.js` skips the `<audio>` element and builds the same analysis graph from a `feed-worklet.js` node (`lsd-feed`, no inputs) whose output goes to `analysisIn`; the analysers also hang off a muted gain to the destination so the graph keeps being pulled. `feedring.js` is the worklet's mono ring buffer with a linear resampler (stream rate to context rate), a 40 ms prefill, and a skip-ahead to 80 ms when more than 300 ms is queued, so the picture stays close to the sound. `feedPCM(data, rate)` accepts Int16Array, Float32Array, ArrayBuffer (little-endian int16) or base64 and posts to the worklet (transferring buffers it decoded itself). It returns false until the graph exists (`LSD.feedReady()`; `lsd-embed-ready` event).
- **Silence is not "no signal":** `updateSignal` pins `cvState.noSignal` false in embed mode; there is no reconnect logic.
- **What is off:** microphone (`micAvailable()` false), service worker, `status-json` polling, media session, wake lock, bumper, ident, and the relay (`autopilot.setRelayEnabled`, off until the `live` option).
- **Host API (`embed.js`, installed on `window.LSD` by `renderer.js`):** `feed`, `feedReady`, `setOption(name, value)` (`quality`, `reactivity` 0.25..2 with 1 the default, `reducedMotion`, `live`, `sync`), `pause`, `resume`, `next`, `prev`, `hold`. `quality: 'low'` turns heavy scenes off and floors the render scale at the third step (`adapt.ceiling`); `pause` stops the render loop and suspends the AudioContext, `resume` restarts both and resets the frame clock.
- **Host controls (`embed.js`, `autopilot.js` "Host controls"), for the VJ app; Spaz Radio uses none:** `catalog()` (`contentCatalog`: scenes by channel with tags, source, pinned chain, skipped, runnable; backgrounds by index; FX chains and transitions by id with `inRotation`), `state()`, `next`, `prev`, `random`, `channel(n)` (`tuneTo`), `roll`, `hold(on)`, `time(bars)`, `autoRoll(bars)`, `effects(on)`, `nextChain`, `chain(id|null)` (`setChain`: on the scene on air now), `lockChain(id|null)` and `lockTransition(id|null)` (every later scene or change takes it instead of the rotation's pick; a scene coming back from history is rechained; backgrounds, built with `buildDeck(line, true)`, never take a locked chain), `follow(on)`, `backgroundMode(mode)`, `nextBackground`, `prevBackground`, `background(i)` (`tuneBackground`), `skip`, `restore(name)`, `setSkipped(names)`. Each does nothing during a live broadcast and returns the autopilot's answer (`'ok'`, `'live'`, `'off'`, `'unknown'`, ...; some are promises, so a WebView host should read the pushed state rather than `evaluateJavascript`'s result). **State push:** `state()` is `nowShowing()` + `controlState()` (hold, holdBars, autoRollBars, follow, effects, bgMode, lockedChain, lockedTransition, live, broadcaster) + bpm, beatLocked (the relay clock's while live) and paused; it goes to `window.LSDHost.state(json)` if the host defines it, after each command, on `lsd-now-showing`, and on a 1 s check, only when it changed. Test: `tests/web/embed.spec.ts`.
- **Render budget and photo-less builds:** `setOption('maxPixels', n)` replaces embed's 1280x720 render budget (320x180 to 3840x2160's worth; the scaler restarts at its quality floor), for a host driving an external display. At start the autopilot reads `gallery.json`: with no images (an app synced with `--no-gallery`) gallery backgrounds are not runnable (`catalog().backgrounds[i].runnable` false) and the first background is the first runnable line; the web TV, which always has photos, still starts on the gallery.
- **Frame rate over sharpness:** in embed mode `renderer.js` uses a 1280x720-pixel budget, seven scale steps down to 25%, steps down after 1 s above 19 ms (not 2 s above 22 ms) with 1.5 s between steps, and forces `gpu.heavy` false (the probe's `gl.finish()` returned in 0.4 ms on a Pixel 7a, so it can't tell). `?embed&debug` shows fps, render size, scale and heavy state in a corner and logs a status line every 2 s.
- **Sync:** the host's sound reaches the speaker after the audio sink's buffer, so the feed leads what is heard; set the `sync` option to delay the picture to match.
- **Checks:** `node --test web/tools/feedring.test.mjs`; `node web/checks/embed_check.mjs` (headless Firefox: loads the page with `?embed`, pushes a synthetic 124 BPM kick track in real time, expects the signals, the beat lock, no snow in silence, options, pause/resume and a non-black picture).

## 6c. Content Updates for the Spaz Radio App

`scripts/publish_web_tv.sh` also publishes a signed manifest to `https://spaz.org/tv/update/` so the app can
fetch new presets and playlists without an app release. `scripts/make_content_manifest.py` lists the data
files of `web/` (presets, playlists, shaders, FX chains, transitions, `catalog.json`, `settings.json`,
`mandala_recipes.json`, `autopilot.json`) with sha256 and size; JS/HTML/CSS are never listed (the engine ships
with the app). `manifest.json.sig` is an ECDSA P-256/SHA-256 signature over the exact manifest bytes. The
private key is `~/.config/liquid-lsd/content-signing.pem` (not in the repo; back it up, losing it means an app
release to change the key); the public key is `scripts/content_signing_pub.pem`.

Publishing validates content first (`web/tools/content.test.mjs`) and uploads the manifest last. `CONTENT_ENGINE`
in the script is the engine level the content needs: bump it when new content depends on a web feature old apps
lack, so those apps skip the update. Level 2 (2026-11-01): `audio` / `audioFFT` inputs (`web/audiotex.js`), for
Spectrogram and Scope; an app release has to declare engine 2 before it takes content updates again. Level 3 (2026-11-03):
source `gallery` (`web/gallery.js`, the photo-gallery background that `default_bg.lsdplay` starts with); an app
release that bundles it has to declare engine 3 (`ContentUpdater.ENGINE` in `android/lsd-visuals`). `rsync --delete` leaves `update/` alone.

## 6d. The Android Module (`android/lsd-visuals/`)

Everything an Android app needs to show the visuals, shared by Spaz Radio and the VJ app (plan:
`.planning/vj-app-plan.md`): `LsdPage` (a WebView serving the bundled `?embed` page from
`https://appassets.androidplatform.net/visuals/`, downloaded content overlaid, the `LSDHost` bridge, the
`setOption`/`pause`/`resume`/`feed` calls), `LsdPlayer` (one running picture outside Compose: startup timeout,
renderer-crash restarts, battery-saver quality, the delayed audio feed), `LsdVisuals` (the Compose element around a
player; it pauses from the lifecycle observer itself, since a stopped activity gets no recomposition),
`LsdPresentation` (a player on a second display, with a `PixelCopy` snapshot for previews), `LsdControl` /
`LsdState` / `LsdCatalog` (the host controls of section 6b), `PcmTap` (16-bit PCM in from any
source, mono 40 ms chunks out), `VisualsSettings`, and the content updater of section 6c (`ContentStore`,
`ContentUpdater`, `ContentUpdates`: daily WorkManager job `lsd-visuals-content-update`, which also cancels the
name Spaz Radio 2.0 used). Package `lsd.liquid.visuals`.

Apps carry a committed copy as a Gradle module (`include(":lsd-visuals")`), made by
`scripts/sync_lsd_visuals.sh APP_DIR [--no-gallery]`: it copies the module, writes the engine (what `?embed`
loads; no checks, tools, service worker, icons or fonts) into the copy's `src/main/assets/visuals/` with the
gallery at 768 px (`gallery_curate.py export`), and the liquid-lsd commit into `VERSION`. In liquid-lsd itself
the module has no assets (gitignored) and no Gradle build of its own; its unit tests run in an app
(`./gradlew :lsd-visuals:testDebugUnitTest`). The module's `build.gradle.kts` names plugins without versions
and pins its dependencies to the versions Spaz Radio locks; the app supplies the plugins.

## 7. Relay Server Operations (`server/server.js`)

The relay server is a zero-dependency Node.js service using `ws`.

### Environment Variables
- `LSD_PORT`: Port to listen on (default: `9004`).
- `LSD_HOST`: Host interface to bind to (default: `0.0.0.0`).
- `LSD_TOKEN`: Broadcaster authorization secret. **Required**: the relay exits at startup without it, so no shared default can let a stranger broadcast.

### CLI Management
```bash
# Run standalone
./server/lsd_relay start

# Or deploy via PM2
cd server
npm install
pm2 start server.js --name lsd-relay
pm2 save && pm2 startup
```

### Health & Monitoring Endpoint
`GET /health` returns live telemetry JSON:
```json
{
  "status": "ok",
  "viewers": 42,
  "broadcasterConnected": true,
  "uptime": 128450
}
```
- **Fullscreen and microphone (`web/ui.js`, `web/dsp.js`)**: `F` / MENU › Fullscreen / double-click all run `toggleFullscreen` on `#tv-screen-area`. `A` / MENU › Input run `toggleMic` → `dsp.setMic`: every analyser and the onset worklet hang off one `analysisIn` gain that the radio's element source and the `getUserMedia` stream (echo cancellation, noise suppression and AGC off) both feed; only the radio also goes to the volume gain, so the mic never plays back. The radio element is paused while the mic is in, `reconnect()` is skipped, silence still shows NO SIGNAL, `stopAudio` releases the mic, and the `lsd-mic` event refreshes the menu (also when the browser revokes the mic). The headless check only verifies the menu rows; the mic itself needs a real browser.
